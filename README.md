# ESP_TEST

Утилита для проверки **реального** объёма памяти плат на ESP32 (ESP32, S2, S3, C2, C3, C5, C6,
H2, P4, ESP8266): flash и SRAM. Умеет прошивать любой `.bin`, полностью стирать микросхему и
делать разрушающий тест всей flash с резервной копией.

Один exe, никаких установок: **esptool уже вшит внутрь**, Arduino IDE, PlatformIO и ESP-IDF на
компьютере не нужны.

```
dist/ESP_TEST.exe
```

**Версия:** 1.0.0

## Что именно проверяется

### Чип: что это за железо
| Проверка | Откуда данные |
|---|---|
| Модель, маркировка, ревизия | ROM-загрузчик (chip ID, eFuse) |
| MAC и принадлежность пулу Espressif | eFuse + таблица OUI |
| **Wi-Fi / Bluetooth / IEEE 802.15.4** | флаги возможностей из eFuse и ROM |
| Встроенная flash / PSRAM в корпусе | eFuse (pkg_version) |
| Ядро и частота | eFuse |
| Secure Boot, шифрование flash, JTAG, USB | `get_security_info()` — реальные флаги eFuse |
| Что залито в плату | заголовок приложения: проект, версия, ESP-IDF, дата сборки |
| Совпадение образа и чипа | chip ID в заголовке образа против chip ID чипа |

**Важно про Wi-Fi.** Программа показывает **наличие радио в кристалле** и его состояние (не
отключено ли на уровне eFuse). Живую проверку — сканирование сетей, подключение к точке
доступа — может дать только прошивка платы: ROM-загрузчик не поднимает радио, и никакая
программа «через COM-порт» этого сделать не может.

### Flash (главное)
| Проверка | Как делается |
|---|---|
| Реальный объём | команда RDID (0x9F) у самого flash-чипа → JEDEC ID → производитель и ёмкость |
| Перекрёстная проверка | автоопределение загрузчика (SFDP / таблица esptool) |
| Что заявлено | размер в заголовке прошивки (байт 3 bootloader-образа) |
| Что размечено | разбор таблицы разделов, суммарный размер и конец последнего раздела |
| Вердикт | «объём подтверждён» / «заявлено больше, чем есть» (типичный обман на дешёвых модулях) / «заявлено меньше» |

### Прошивка любого .bin
Блок **«Прошить .bin»**: кнопка «Выбрать файл…», поле адреса (по умолчанию `0x0`) и кнопка
«Прошить файл».

* подходит любой образ: слитый (`merged`) на `0x0`, отдельные `bootloader.bin` / `partitions.bin` /
  `firmware.bin` по своим адресам, образы LittleFS/SPIFFS, произвольные дампы;
* адрес можно писать как `0x10000`, `65536` или `0`; если он не кратен сектору (4096),
  программа выравнивает начало вниз и добивает пропуск байтами `0xFF`, о чём пишет в журнал;
* файл, который не влезает во flash по указанному адресу, отклоняется с понятной ошибкой;
* галочка **«Проверять»** — после записи образ читается обратно и сравнивается побайтно,
  сообщается первый несовпавший блок;
* галочка **«Перезагрузить»** — после записи плата перезапускается. Снимите её, чтобы залить
  несколько файлов подряд (bootloader → разделы → app), а потом нажать «Сбросить плату (RST)»;
* после прошивки полного образа (`0x0`) паспорт flash перечитывается автоматически.

Скорость на ESP32-C3 через нативный USB — около 360 КБ/с: образ 2.2 МБ пишется примерно за 6 с,
столько же занимает проверка.

### Стирание flash (полное, необратимое)
Кнопка **«Стереть flash полностью»** очищает микросхему целиком — загрузчик, таблицу разделов,
приложение, NVS, файловую систему, coredump.

* резервная копия **не создаётся** — данные исчезают безвозвратно;
* подтверждение вводится вручную: нужно набрать слово `СТЕРЕТЬ`, до этого кнопка заблокирована;
* после стирания программа проверяет чтением, что начало flash действительно `0xFF`,
  перезагружает плату и закрывает сессию;
* если на чипе включён **Secure Boot** или шифрование flash, загрузчик откажется стирать —
  программа честно сообщит об этом, а не будет ломать плату;
* чтобы плата снова заработала, её нужно прошить: блок «Прошить .bin», Arduino IDE или ESP-IDF.

### Глубокий тест Flash (по желанию, разрушающий)
Записывает во всю flash псевдослучайный шаблон, читает обратно и сравнивает блок за блоком.

* перед тестом снимается **полная резервная копия** (по умолчанию в `Documents`);
* после теста прошивка **автоматически восстанавливается** и проверяется;
* прерывание (кнопка «Прервать») не ломает плату: восстановление выполняется всё равно;
* если чип «меньше, чем написано на корпусе», ошибки начнутся с определённого адреса —
  программа покажет первый сбойный блок и оценит реальную ёмкость;
* попутно измеряется скорость записи и чтения.

⚠️ Во время теста прошивка и данные (NVS, SPIFFS/LittleFS) временно стираются.
Не отключайте плату от USB.

### ОЗУ
* встроенная SRAM — объём задан моделью чипа (520 КБ у ESP32, 512 КБ у S3/C6, 400 КБ у C3…),
  подделывать её невозможно, поэтому объём берётся из справочника Espressif;
* тест **шины данных**: 68 шаблонов (0x00, 0xFF, 0x55, 0xAA, «шагающая единица» и инверсия)
  записываются и читаются обратно в свободную область SRAM ниже stub-загрузчика;
* тест **шины адреса**: 8 независимых ячеек с разными значениями — ловит обрыв и залипание
  адресных линий;
* внешняя PSRAM **не измеряется** через ROM-загрузчик: до запуска прошивки она не
  инициализирована, и любое обращение к её адресам ничего не значит. В интерфейсе показывается
  типовая ёмкость для модели и пояснение.

## Как пользоваться

1. Подключите плату USB-кабелем (нужен data-кабель, не «только зарядка»).
2. Запустите `ESP_TEST.exe` — **плата найдётся и подключится сама**.
3. Список портов опрашивается каждые 1.5 с: плата, воткнутая после запуска, появится в списке и
   будет выбрана автоматически (USB-порты первыми, COM1 материнской платы — последним).
   Галочка «Подключаться автоматически» отключает автоподключение.
4. **Ручной выбор порта**: все найденные порты показаны списком в блоке «Соединение». Нажмите
   нужную строку (или выберите порт в выпадающем списке в шапке) — режим переключится на
   `ПОРТ · ВРУЧНУЮ`, автопоиск выключится, и программа будет работать только с этим портом.
   Если выбранная плата пропадёт и появится снова, программа подключится именно к ней, а чужие
   платы трогать не будет. Вернуть автопоиск — галочка «Искать плату на всех портах».
5. **Горячая замена**: выдернули одну плату, воткнули другую — программа сама заметит пропажу
   порта (или что на том же COM оказалась другая плата по VID:PID), закроет сессию, найдёт новую
   плату и подключится к ней. Раз в ~7 с идёт тихая проверка связи, чтобы поймать замену платы
   на том же самом COM-номере.
6. Если портов нет вообще, в блоке «Соединение» пишется причина: либо «USB-устройств
   Espressif/USB-UART в системе нет» (кабель, порт, питание), либо «USB-устройство `VID:PID`
   воткнуто, но COM-порт не создан» (не установлен драйвер USB-UART).
7. Вкладки: **Чип** — модель, возможности, безопасность, прошивка; **Flash** — паспорт чипа flash
   и вердикт; **ОЗУ** — тест SRAM; **Отчёт** — готовый текст и кнопка «Сохранить отчёт»;
   **Журнал** — что происходит сейчас.
8. Блоки **«Прошить .bin»** и **«Стереть прошивку»** — запись любого образа и полная очистка
   микросхемы (см. разделы выше).

Кнопка **⟳** — принудительное обновление списка портов.

Если автоматический вход в загрузчик не сработал: зажмите **BOOT**, нажмите и отпустите
**EN/RST**, отпустите **BOOT**, затем нажмите «Подключиться». Скорость можно снизить до 115200
в блоке «Соединение».

### Демо-режим
`ESP_TEST.exe --demo` — интерфейс с данными виртуальной платы ESP32-S3, без железа (удобно,
чтобы посмотреть, как всё выглядит).

## Требования

* Windows 10/11 x64;
* драйвер USB-UART платы (CP210x, CH340, FTDI) — единственное, что нужно доставить в систему;
  платам с нативным USB (ESP32-S2/S3/C3/C6) драйвер не нужен;
* сам exe ничего не устанавливает и не пишет в реестр.

Файлы, которые создаёт программа: резервные копии flash в `Documents`
(`esp_flash_backup_<порт>_<дата>.bin`) и отчёты, которые вы сохраните вручную.

## Сборка из исходников

```bat
pip install esptool pyserial pyinstaller pillow
python build.py
```

Результат: `dist\ESP_TEST.exe` (~53 МБ, всё внутри: Python, Tk, esptool со stub-загрузчиками
для всех чипов, pyserial).

Проверка сборки без железа:

```bat
dist\ESP_TEST.exe --selftest
type dist\_selftest.txt
```

### Структура проекта

| Файл | Назначение |
|---|---|
| `main.py` | точка входа, оконный режим, `--demo`, `--selftest` |
| `gui.py` | интерфейс на Tkinter (тёмная тема, свои кнопки, карточки, индикаторы) |
| `probe.py` | работа с железом через esptool: чип, flash, стирание, прошивка `.bin`, глубокий тест, SRAM |

| `build.py` | сборка одного exe и генерация иконки |

## Ограничения

* Глубокий тест — разрушающая операция; при сбое питания в момент восстановления плату придётся
  прошить заново (загрузчик стирается вместе со всем остальным).
* Стирание flash необратимо: резервная копия не делается, прошивку придётся заливать заново.
* На плате с включённым Secure Boot или шифрованием flash стирание запрещено самим чипом.
* Тест SRAM проверяет целостность ячеек, но не «объём»: объём SRAM — свойство кристалла.
* PSRAM, шифрование flash и Secure Boot не тестируются — только читаются их флаги.
* Скорость чтения и записи зависит от USB-UART и режима загрузчика: на 921600 бод ориентируйтесь
  на 100–150 КБ/с у внешнего USB-UART и ~360 КБ/с у нативного USB.
